# doc/ — 技术方案文档流程

需求开发与问题修复的统一工作流：**先方案、后编码、同步文档**。

## 流程

1. **立项**：需求或问题确认后，复制 [_template.md](_template.md) 在 `doc/active/` 创建方案文档，命名 `YYYY-MM-DD-主题.md`；先写清背景、方案选型与验证方式，**与需求方对齐后再动手**。
2. **执行**：按方案实施；代码变更若偏离方案（改路径、换实现、砍范围），**当天回写**到该文档的「实施记录 / 方案调整」，保持文档与代码一致。
3. **归档**：需求完成并验证上线后，文档移入 `doc/archive/`（文件名不变），文末补「结论」；其中的**重点事项或方案调整**合并回 [../README.md](../README.md) 的「项目基线」章节（重大演进时更新基线日期）。

## 目录

- `active/` — 进行中的技术方案（同一时期可有多份）
- `archive/` — 已完结归档（含立项时的 [DESIGN.md](archive/DESIGN.md)）
- `_template.md` — 方案模板

## 约定

- 方案文档是**决策记录**不是流水账：写清「为什么这么选、放弃了什么、踩了什么坑」，后人（包括未来的自己和 agent）能据此理解决策。
- 小修小补（文案、样式微调、重命名）可不开方案，直接在 commit message 说清即可；行为变更、数据契约变更、新增交互**必须**走本流程。
- 数据契约变更同时受 [data/SCHEMA.md](../data/SCHEMA.md) 三同步约束（契约文档 + 校验器 + 数据）。
